Never include secrets, API keys, tokens or private keys — the scanner rejects them on sight, and we never ask for passwords.

3. Substance rule — "verify it serves"

A submission must carry something real: files, code, a verifiable repo_url, or a working test.url. Description-only submissions (vaporware: no code, dead links) are never merged into the catalog — they stay in the queue as pending-L2: description-only with trust capped at 45. If your claims are false (repo 404, package 404) the submission is rejected at the door with actionable reasons.

4. Verdicts

ACCEPTED HTTP 201 — stored in the public, auditable queue (github.com/alicelabs-llc/marketnow-submissions), status certified-L1.5 (auto-scan + claims verified), trust score 25-60, pending L2 review and catalog merge.

ACCEPTED (description-only) HTTP 201 — stored as pending-L2: attach files, code or a verifiable repo to become merge-eligible. Trust capped at 45.

REJECTED HTTP 422 — machine-reviewable reasons returned, including false claims (repo 404, install package 404). Fix and resubmit; dry-run as often as you want.

Submissions start YELLOW risk: new skills have zero adoption history, so trust is earned — registry signals, usage and L2 review raise it over time.

5. AI agents: submit via MCP

The MarketNow MCP server exposes a dedicated write tool. Any MCP client (Claude, Cursor, custom agents, ChatGPT via a custom MCP connector) can call it:

{
  "tool": "marketnow_submit_skill",
  "arguments": {
    "skill": { "name": "...", "version": "1.0.0", "description": "...", "author": "..." },
    "dry_run": false
  }
}

Same pipeline, same verdict, same queue — straight from your agent session.

6. What happens after acceptance

  1. Stored & certified-L1.5 — your package and its full scan report live in the public queue (audit trail forever).
  2. L2 review — claims re-verified (repo, install), substance checked. False claims discovered later → quarantined-L2 in the queue, never merged.
  3. Catalog merge — accepted skills with real substance join the indexed catalog with their own /s/<slug> page, searchable by 69k+ catalog users and every MCP client.
  4. Track anytime — GET /api/submissions or the GitHub queue.

Limits & honesty

Rate limit: 8 submissions per source per hour (queue-backed, durable) + anti-flood protection. Payload: 100KB. L1.5 is a static auto-scan + live claim verification: it certifies structure, safety signals and that your claims resolve — it does not execute your code. L2 is the deeper review. Trust is a heuristic over public signals — not a guarantee. Vaporware is not a product: if the repo is 404 or the install package does not exist, you get a 422, not a catalog page.
